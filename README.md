# E-Saraban ระบบสารบรรณอิเล็กทรอนิกส์

ระบบสารบรรณอิเล็กทรอนิกส์สำหรับสำนักงาน ป.ป.ช. ประจำจังหวัดเชียงใหม่ (ระบบทดลอง)

> **ข้อห้าม:** ระบบนี้เป็นระบบทดลอง ห้ามใช้ข้อมูลจริงหรือข้อมูลลับของสำนักงาน
> และห้ามเชื่อมต่อกับระบบหรือข้อมูลราชการจริงโดยไม่ได้รับอนุญาต

## ลงปฏิทินจากไฟล์

อ่านชื่องาน วันที่ เวลา สถานที่ และเรื่องจากหนังสือ โดยลองตัวอ่านหลายตัว (pdfium, pdftotext, pypdf) แล้วเลือกผลที่ข้อความสะอาดและข้อมูลครบที่สุด
ถ้ายังไม่พอหรือเป็นภาพสแกนจะอ่านด้วย OCR ภาษาไทย (tesseract) ทั้งหมดติดตั้งใน Docker image
ผู้ใช้ตรวจแก้แล้วเลือก "เพิ่มลง Google Calendar" (เปิดหน้า Google Calendar ของผู้ใช้พร้อมข้อมูล ไม่ต้องตั้งค่าบัญชี Google ในระบบ)
หรือดาวน์โหลดไฟล์ .ics หนังสือชั้นความลับส่งไป Google ไม่ได้ ทุกการส่งออกบันทึกใน Audit Log
ปิด OCR ได้ด้วย `ESARABAN_OCR_ENABLED=False` บนเครื่องพัฒนา Windows ที่ไม่มี tesseract ระบบจะอ่านได้เฉพาะ PDF ที่มีข้อความ

## หน้าตาระบบ

สีหลักใช้ม่วงและทองจากตราสำนักงาน ป.ป.ช. ภาพตราอยู่ที่ `static/img/` (`nacc-emblem.png` ใน sidebar, `nacc-emblem-lg.png` ในหน้าเข้าสู่ระบบ, `favicon.png`)
ถ้าจะเปลี่ยนภาพตรา ให้ใช้ PNG พื้นใสขนาดเดิม แล้วรัน `up -d --build`
หัวหนังสือราชการที่ระบบสร้างยังใช้ตราครุฑตามระเบียบงานสารบรรณ (ตั้งที่เมนูหัวหนังสือ) ไม่ใช้ตรานี้

│   ├── audit/            Audit Log
│   └── reports/          Dashboard และรายงาน
├── templates/            HTML templates
├── static/               CSS และไฟล์ vendor (Bootstrap, ฟอนต์ Sarabun)
├── scripts/              สคริปต์สร้างฐานข้อมูล ดาวน์โหลดไฟล์ vendor และสำรองข้อมูล

## A. ติดตั้งด้วย Docker

ระบบจะรัน 3 ส่วน: `db` (PostgreSQL), `web` (Django + Gunicorn) และ `nginx` (HTTPS)
ฐานข้อมูลไม่เปิดพอร์ตออกนอกเครื่อง ผู้ใช้เข้าได้ทาง HTTPS ผ่าน nginx เท่านั้น

### A1. ติดตั้ง Docker

- **ทดลองบน Windows:** ติดตั้ง Docker Desktop (ต้องเปิด WSL 2 ตามที่ตัวติดตั้งแนะนำ) แล้วเปิดโปรแกรมค้างไว้
- **Server จริง:** ให้ฝ่าย IT ติดตั้ง Docker Engine พร้อม Compose plugin บน Linux server ภายใน

ตรวจด้วย:

```powershell
docker --version
docker compose version
```

### A2. ตั้งค่า

```powershell
Copy-Item .env.docker.example .env.docker
docker run --rm python:3.12-slim python -c "import secrets; print(secrets.token_urlsafe(50))"
```

(บน Linux ใช้ `cp` แทน `Copy-Item`)

เปิด `.env.docker` แล้วแก้:
- `SECRET_KEY` ใส่ค่าที่คำสั่งด้านบนพิมพ์ออกมา
- `POSTGRES_PASSWORD` ตั้งรหัสผ่านฐานข้อมูล (ตัวอักษรและตัวเลข)
- (แนะนำ) เพิ่ม `POSTGRES_APP_USER=esaraban_rt` และ `POSTGRES_APP_PASSWORD=` รหัสผ่านอีกชุด (อย่างน้อย 16 ตัว)
  ระบบจะใช้ผู้ใช้ฐานข้อมูลแบบจำกัดสิทธิ์นี้ขณะทำงาน ดู [คู่มือติดตั้ง](docs/install.md) ข้อ 3.2
- **สำรองไฟล์ `.env.docker` เก็บแยกไว้** ถ้าหาย จะเปิดไฟล์เอกสารที่สำรองไว้ไม่ได้
- บน server จริง แก้ `SERVER_NAME`, `ALLOWED_HOSTS` และ `CSRF_TRUSTED_ORIGINS` เป็นชื่อเครื่องที่ผู้ใช้จะเข้า เช่น `esaraban.local`

### A3. เริ่มระบบ

```powershell
docker compose --env-file .env.docker up -d --build
docker compose --env-file .env.docker ps
```

ครั้งแรกใช้เวลาหลายนาที เพราะต้องดาวน์โหลดและ build image
รอจนคอลัมน์ STATUS ของทั้ง 3 ส่วนขึ้น `healthy` หรือ `Up`

ถ้ามีปัญหา ดู log ได้ด้วย:

```powershell
docker compose --env-file .env.docker logs web
```

### A4. สร้างผู้ดูแลระบบและรันเทสต์

```powershell
docker compose --env-file .env.docker exec web python manage.py createsuperuser
```

รันเทสต์ (ใช้ settings ของเครื่องพัฒนาเฉพาะคำสั่งนี้ เพราะ settings จริงบังคับ HTTPS):

```powershell
docker compose --env-file .env.docker exec -e DJANGO_SETTINGS_MODULE=config.settings.dev web python manage.py test apps --noinput
```

ผลที่ถูกต้องคือ `Ran 240 tests` ตามด้วย `OK`

### A5. เปิดระบบ

เปิด https://localhost (หรือ https://ชื่อเครื่องที่ตั้งใน SERVER_NAME)
แล้วเข้าสู่ระบบที่ https://localhost/admin/ ด้วยผู้ดูแลระบบจากข้อ A4
จากนั้นเปิด https://localhost/system/status/ เพื่อดูหน้าสถานะระบบ

เบราว์เซอร์จะเตือนว่าการเชื่อมต่อไม่ปลอดภัย เพราะช่วงทดลองระบบใช้ใบรับรอง self-signed ที่สร้างเอง
บนเครื่องทดลองกด "ขั้นสูง" แล้ว "ดำเนินการต่อ" ได้
**ห้ามใช้ใบรับรองทดลองกับระบบจริง** ให้นำใบรับรองของหน่วยงานมาใส่ตามข้อ A6

### A6. ใช้ใบรับรอง HTTPS ของหน่วยงาน

วางไฟล์ `server.crt` (รวม intermediate certificate) และ `server.key` ในโฟลเดอร์ `docker/certs` แทนไฟล์เดิม
แก้ `SECURE_HSTS_SECONDS=31536000` ใน `.env.docker` แล้วรัน:

```powershell
docker compose --env-file .env.docker up -d --force-recreate
```

### A7. หยุด อัปเดต และสำรองข้อมูล

```powershell
docker compose --env-file .env.docker down                    # หยุดระบบ (ข้อมูลยังอยู่)
docker compose --env-file .env.docker up -d --build           # อัปเดตหลังได้โค้ดเวอร์ชันใหม่
```

**ห้ามใช้ `down -v`** เพราะจะลบฐานข้อมูลและไฟล์เอกสารทั้งหมด

สำรองและกู้คืนข้อมูล:

```bash
sh scripts/backup.sh                                  # Linux
sh scripts/restore.sh backups/วันที่-เวลา
```

```powershell
powershell -ExecutionPolicy Bypass -File scripts\backup.ps1          # Windows
powershell -ExecutionPolicy Bypass -File scripts\restore.ps1 backups\วันที่-เวลา
```

ได้โฟลเดอร์ `backups/วันที่-เวลา` ที่มีไฟล์ฐานข้อมูล ไฟล์เอกสาร และ checksum
การตั้งเวลาอัตโนมัติ กฎ 3-2-1 และการซ้อมกู้คืน ดู [การสำรองและกู้คืนข้อมูล](docs/backup-restore.md)

### พอร์ตที่ใช้

ระบบใช้พอร์ต 80 และ 443 ของเครื่อง ถ้ามีโปรแกรมอื่นใช้อยู่ `up` จะขึ้น error ว่า port is already allocated
ให้ปิดโปรแกรมนั้นก่อน

## B. การติดตั้งบน Windows + VS Code (สำหรับนักพัฒนา)

### 0. โปรแกรมที่ต้องมี

- Python 3.12 ขึ้นไป (ตอนติดตั้งติ๊ก **Add python.exe to PATH**)
- PostgreSQL 16 (จำรหัสผ่านของผู้ใช้ `postgres` ที่ตั้งตอนติดตั้ง)
- Git for Windows
- VS Code พร้อม extension **Python** (Microsoft)

ตรวจว่าติดตั้งครบ โดยเปิด **Terminal ใน VS Code** (เมนู Terminal › New Terminal) แล้วพิมพ์:

```powershell
python --version
git --version
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" --version
```

ทั้ง 3 คำสั่งต้องแสดงเลขเวอร์ชัน ถ้า `python` เปิด Microsoft Store ขึ้นมา แปลว่ายังไม่ได้ติ๊ก Add to PATH ให้ติดตั้ง Python ใหม่

### 1. เปิดโปรเจกต์

1. แตกไฟล์ zip ไปที่ เช่น `C:\Projects\esaraban`
2. VS Code › File › Open Folder › เลือกโฟลเดอร์ `esaraban`
3. เปิด Terminal ใหม่ (ต้องอยู่ที่โฟลเดอร์ `esaraban`)

### 2. สร้าง virtual environment และติดตั้งแพ็กเกจ

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements-dev.txt
```

ถ้าขึ้นข้อความ *running scripts is disabled on this system* ให้รันคำสั่งนี้ครั้งเดียว แล้วรัน `Activate.ps1` ใหม่:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

เมื่อสำเร็จ หน้าบรรทัดคำสั่งจะมี `(.venv)` นำหน้า
จากนั้นกด `Ctrl+Shift+P` › **Python: Select Interpreter** › เลือก `.venv`

### 3. สร้างฐานข้อมูล

ตั้งรหัสผ่านสำหรับผู้ใช้ฐานข้อมูลของระบบ (ใช้ตัวอักษรภาษาอังกฤษและตัวเลขเท่านั้น) แล้วรัน:

```powershell
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres -v app_password=รหัสผ่านที่ตั้ง -f scripts\create_db.sql
```

ระบบจะถามรหัสผ่านของผู้ใช้ `postgres` เมื่อสำเร็จจะเห็น `CREATE ROLE`, `ALTER ROLE`, `CREATE DATABASE`

### 4. ตั้งค่า .env

```powershell
Copy-Item .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(50))"
```

เปิดไฟล์ `.env` ใน VS Code แล้วแก้ 2 บรรทัด:

- `SECRET_KEY=` ใส่ค่าที่คำสั่งด้านบนพิมพ์ออกมา
- `DATABASE_URL=` เปลี่ยน `CHANGE_ME` เป็นรหัสผ่านที่ตั้งในข้อ 3

### 5. ดาวน์โหลด Bootstrap และฟอนต์ Sarabun

```powershell
powershell -ExecutionPolicy Bypass -File scripts\download_vendor.ps1
```

ต้องเห็น `OK` 10 บรรทัด และ `All files downloaded.`
ไฟล์จะเก็บในโปรเจกต์ ระบบจึงไม่ต้องต่ออินเทอร์เน็ตตอนใช้งาน

### 6. สร้างตารางในฐานข้อมูล

```powershell
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py migrate
```

- `check` ต้องขึ้น `System check identified no issues (0 silenced).`
- `makemigrations --check` ต้องขึ้น `No changes detected` (ตรวจว่าไฟล์ migration ตรงกับโมเดล)
- `migrate` ต้องขึ้น `OK` ทุกบรรทัด

### 7. สร้างผู้ดูแลระบบคนแรก

```powershell
python manage.py createsuperuser
```

รหัสผ่านต้องยาวอย่างน้อย 12 ตัวอักษร

### 8. รันทดสอบ

```powershell
python manage.py test apps --noinput
```

ผลที่ถูกต้องคือ `Ran 240 tests` ตามด้วย `OK`

### 9. เปิดระบบ

```powershell
python manage.py runserver
```

เปิดเบราว์เซอร์ที่ http://127.0.0.1:8000 จะเห็นหน้า **สถานะระบบ**
ทุกรายการต้องเป็นเครื่องหมายถูก ยกเว้น `pg_trgm` ซึ่งยังไม่จำเป็นในขั้นนี้

หรือกด `F5` ใน VS Code แล้วเลือก **Django: runserver** เพื่อรันแบบ debug ได้

ทดสอบเข้า http://127.0.0.1:8000/admin/ ด้วยผู้ดูแลระบบจากข้อ 7
แล้วลองเพิ่ม **กลุ่มงาน** และ **ผู้ใช้** ได้

- เข้าสู่ระบบที่ `/accounts/login/` ทุกคนต้องใช้ MFA (แอป Microsoft Authenticator หรือ Google Authenticator)
  ครั้งแรกจะให้สแกน QR และแสดงรหัสสำรอง 10 รหัส ซึ่งแสดงเพียงครั้งเดียว
- ใส่รหัสผ่านหรือรหัส MFA ผิด 5 ครั้งใน 15 นาที บัญชีจะถูกระงับชั่วคราว 15 นาที
- หน้า login ของ Django admin ถูกปิด ทุกคนต้องเข้าผ่านหน้าที่มี MFA
- ผู้ดูแลระบบจัดการผู้ใช้ที่เมนู **ผู้ใช้และสิทธิ์** และ **กลุ่มงาน**
  ผู้ใช้ใหม่ได้รหัสผ่านชั่วคราว และต้องเปลี่ยนเองเมื่อเข้าสู่ระบบครั้งแรก
- บทบาท 6 แบบ กำหนดขอบเขตเป็นกลุ่มงานได้ (ครอบคลุมกลุ่มงานย่อยด้วย) หรือเว้นว่างเพื่อใช้ทั้งสำนักงาน
- สิทธิ์ของแต่ละบทบาทกำหนดไว้ที่ `apps/accounts/permissions.py`
- ผู้ใช้เปลี่ยนมือถือ: ผู้ดูแลกด **รีเซ็ต MFA** ที่หน้าผู้ใช้นั้น

ข้อควรรู้: กุญแจเข้ารหัส MFA สร้างจาก `SECRET_KEY` ถ้าเปลี่ยน `SECRET_KEY` ผู้ใช้ทุกคนต้องตั้งค่า MFA ใหม่
(หรือตั้ง `MFA_ENCRYPTION_KEY` แยกไว้ตั้งแต่ต้น)

## ทะเบียนรับและทะเบียนเลข (ขั้นตอนที่ 6)

- ชุดทะเบียนเริ่มต้น 5 ชุด (รับ ส่ง บันทึกข้อความ คำสั่ง ประกาศ) ผู้ดูแลระบบแก้ชื่อและรูปแบบเลขได้ที่หน้าทะเบียนเลข
  รูปแบบเลขใช้ `{org}` รหัสหน่วยงาน, `{no}` เลขลำดับ (`{no:04d}` = เติม 0 ให้ครบ 4 หลัก), `{year}` ปี พ.ศ.
- เลขนับใหม่ทุกปี พ.ศ. (ตามปีปฏิทิน) ออกเลขด้วย database transaction และล็อกแถว จึงไม่ซ้ำแม้กดพร้อมกัน
- เลขที่ออกแล้วลบไม่ได้ ยกเลิกได้โดยต้องระบุเหตุผล เลขที่ยกเลิกจะไม่ถูกนำกลับมาใช้
- ไฟล์ที่อัปโหลดต้องเป็น PDF จริง ไม่มี JavaScript ไม่ติดรหัสผ่าน ไฟล์ละไม่เกิน 20 MB และถูกเข้ารหัสก่อนเก็บ
- ผู้ใช้เห็นเอกสารตามชั้นความลับและขอบเขตกลุ่มงานของบทบาท ผู้ดูแลระบบและผู้ตรวจสอบไม่ได้สิทธิ์อ่านเอกสารโดยอัตโนมัติ
- การเปิดดู ดาวน์โหลด และแก้ไข ถูกบันทึกในประวัติของเอกสาร
- ชั้น "ลับที่สุด" ปิดไว้ เปิดได้ด้วย `ALLOW_TOP_SECRET=True` ใน `.env.docker` หลังได้รับอนุญาตจากผู้รับผิดชอบเท่านั้น

**สำคัญมาก:** กุญแจเข้ารหัสไฟล์สร้างจาก `SECRET_KEY` ถ้าเปลี่ยนหรือทำ `SECRET_KEY` หาย ไฟล์เอกสารทั้งหมดจะเปิดไม่ได้อีก
ต้องสำรองไฟล์ `.env.docker` ไว้ในที่ปลอดภัย แยกจากข้อมูลสำรอง และห้ามเปลี่ยน `SECRET_KEY` หลังเริ่มใช้งาน

## การเสนอหนังสือ (ขั้นตอนที่ 7A)

- เจ้าหน้าที่สารบรรณกด **เริ่มเสนอ** ในหน้าเอกสาร แล้วเลือกเส้นทาง
- เส้นทางเริ่มต้น: หัวหน้ากลุ่มงานเจ้าของเรื่อง → ผู้บริหารสั่งการ → ผู้รับผิดชอบ
  ผู้ดูแลระบบแก้ไขหรือสร้างเส้นทางใหม่ได้ที่เมนู **เส้นทางการเสนอ** โดยขั้นสุดท้ายต้องเป็นการสั่งการ
- ก่อนเริ่มเสนอ ระบบตรวจว่ามีผู้ใช้ที่มีบทบาทและสิทธิ์ชั้นความลับเพียงพอสำหรับทุกขั้น จึงไม่มีเรื่องค้างเพราะไม่มีผู้รับ
- ทุกขั้นส่งกลับแก้ไขได้ (ต้องระบุเหตุผล) ส่งกลับจากขั้นแรกจะกลับไปที่ผู้เริ่มเสนอ ซึ่งแก้ไขแล้วเสนอใหม่หรือยกเลิกได้
- ผู้บริหารสั่งการและเลือกผู้รับผิดชอบได้หลายคน ผู้รับผิดชอบเห็นเอกสารได้แม้อยู่ต่างกลุ่มงาน
- **มอบหมายปฏิบัติราชการแทน** ตามช่วงวันที่ ระบบบันทึกทั้งผู้มีหน้าที่และผู้ที่กดจริง
- งานที่รอทุกคนอยู่ที่เมนู **งานรอดำเนินการ**

## ตัวดู PDF และการลงนาม (ขั้นตอนที่ 7B)

- กด **เปิดดู** ที่ไฟล์ จะเปิดตัวดู PDF ในหน้าเว็บ (PDF.js) กด **ปักหมุดความเห็น** แล้วคลิกตำแหน่งบนหน้าเพื่อใส่ความเห็น
  ทุกคนที่เห็นเอกสารเห็นความเห็นด้วย ลบได้เฉพาะความเห็นของตนเอง (ระบบเก็บร่องรอยไว้)
- **สั่งการ/เกษียน** (ผู้บริหาร หัวหน้ากลุ่มงาน และเจ้าหน้าที่สารบรรณ): กด **สั่งการ/เกษียน** ที่แถบเครื่องมือ เลือกสีหมึก (น้ำเงิน แดง ดำ เขียว)
  และขนาด (เล็ก กลาง ใหญ่) คลิกบนหน้าเอกสารแล้วพิมพ์ได้เลย กด Ctrl+Enter เพื่อบันทึก ลากย้ายหรือลบข้อความของตนเองได้
- **ลงนาม** (ผู้บริหารและหัวหน้ากลุ่มงาน): อัปโหลดภาพลายมือชื่อที่เมนู **ลายมือชื่อของฉัน** ก่อน (ระบบลบพื้นขาวให้อัตโนมัติ)
  แล้วกด **วางลายเซ็น** คลิกตรงจุดที่จะลงนาม ลากย้ายและปรับขนาดได้
- **ปุ่มเดียว ไฟล์เดียว**: จะสั่งการ/เกษียนอย่างเดียว ลงนามอย่างเดียว หรือทำทั้งสองอย่างก็ได้ แล้วกด **สร้างไฟล์ฉบับใหม่** ครั้งเดียว
  ระบบรวมทุกอย่างเป็นไฟล์ใหม่ไฟล์เดียว ไฟล์เดิมเก็บไว้ครบ ถ้ามีลายเซ็นต้องกรอกรหัส 6 หลักจากแอปทุกครั้ง
  ถ้าสั่งการ/เกษียนอย่างเดียวให้กดปุ่มซ้ำเพื่อยืนยัน ระบบบันทึก hash ของไฟล์และประวัติการสั่งการ/เกษียนและการลงนามไว้
- **ภาพลายมือชื่อไม่ใช่ Digital Signature** ระบบแสดงป้ายแยกชัดเจนทุกจุด ส่วนลายมือชื่อดิจิทัลดูหัวข้อ 7C-2

## หนังสือจากแม่แบบ (ขั้นตอนที่ 7C-1)

- เมนู **สร้างหนังสือ** เลือกแม่แบบ 4 แบบ: หนังสือภายนอก บันทึกข้อความ คำสั่ง ประกาศ กรอกเรื่อง เรียน ข้อความ และผู้ลงนาม
  ระบบสร้าง PDF ตามรูปแบบงานสารบรรณ ตัดคำภาษาไทย ย่อหน้า และขึ้นหน้าใหม่ให้อัตโนมัติ ค้นหา/คัดลอกข้อความในไฟล์ได้
- เอกสารเป็น **ร่าง** (ยังไม่มีเลข) แก้ไขได้จนกว่าจะออกเลข แก้ทุกครั้งได้ไฟล์ร่างฉบับใหม่ ฉบับเดิมเก็บไว้
- ผู้ร่างเสนอร่างตามเส้นทาง "มาตรฐาน: เสนอลงนาม..." (หัวหน้ากลุ่มงาน → ผู้บริหาร) ถ้าถูกส่งกลับแก้ไข แก้ร่างแล้วเสนออีกครั้งได้
- ผู้ลงนามกด **วางลายเซ็น** ระบบวางลายเซ็นตรงที่ว่างเหนือชื่อผู้ลงนามให้ทันที ลากปรับได้
- เจ้าหน้าที่สารบรรณกด **ออกเลขหนังสือ** ที่หน้ารายละเอียด ระบบออกเลขจากทะเบียนที่ตรงประเภท (ส่ง/บันทึกข้อความ/คำสั่ง/ประกาศ)
  แล้วประทับเลขที่และวันที่ลงบนไฟล์หลักล่าสุด (รวมฉบับที่ลงนามหรือสั่งการ/เกษียนแล้ว) ออกเลขแล้วแก้เนื้อหาไม่ได้
- ผู้ดูแลระบบตั้งชื่อส่วนราชการ ที่ตั้ง และอัปโหลดภาพตราครุฑได้ที่เมนู **หัวหนังสือ** (ระบบไม่ได้แนบภาพตราครุฑมาให้)
- ข้อจำกัด: ข้อความในไฟล์วาดเป็นภาพความละเอียดสูง (ประมาณ 288 dpi) พร้อมชั้นข้อความที่ค้นหาได้ เพราะเครื่องมือสร้าง PDF ที่ใช้
  จัดวรรณยุกต์ไทยไม่ได้ ใช้ฟอนต์ Sarabun ขนาด 14 ซึ่งใกล้เคียง TH Sarabun New 16 ตรวจรูปแบบกับผู้รับผิดชอบก่อนใช้งานจริง

## ลายมือชื่อดิจิทัล (ขั้นตอนที่ 7C-2)

- ตอนวางลายเซ็น เลือกประเภท **ลายมือชื่อดิจิทัล** (ค่าเริ่มต้น) หรือ **ภาพลายมือชื่อ** แล้วกรอกรหัส 6 หลักเหมือนเดิม
- ลายมือชื่อดิจิทัลเป็นมาตรฐาน PDF (adbe.pkcs7.detached, RSA-SHA256) เขียนต่อท้ายไฟล์ (incremental update)
  ผู้ลงนามหลายคนลงต่อกันได้ ลายมือชื่อก่อนหน้ายังใช้ได้ ภาพที่เห็นบนเอกสารคือภาพลายมือชื่อพร้อมคำว่า "ใบรับรองทดสอบ ไม่มีผลทางกฎหมาย"
- **ใบรับรองทดสอบ ไม่มีผลทางกฎหมาย**: ระบบสร้าง CA ทดสอบเองเมื่อมีการลงนามดิจิทัลครั้งแรก และออกใบรับรองให้ผู้ลงนามแต่ละคนอัตโนมัติ
  (อายุ 1 ปี ต่ออายุอัตโนมัติ) กุญแจลับเข้ารหัสเก็บใน private storage ไม่ส่งออกไปที่เครื่องผู้ใช้
- ตัวดู PDF ตรวจลายมือชื่อทุกครั้งที่เปิดไฟล์: hash ตรงหรือไม่ ลายมือชื่อถูกต้องหรือไม่ ออกโดย CA ทดสอบของระบบหรือไม่ และมีข้อมูลเพิ่มหลังลงนามหรือไม่
  ไฟล์จากหน่วยงานอื่นที่ลงนามด้วยใบรับรองจริง จะแสดงว่า "ไม่รู้จักผู้ออกใบรับรอง" เพราะระบบเชื่อถือเฉพาะ CA ทดสอบ
- ไฟล์ที่มีลายมือชื่อดิจิทัลแล้ว เขียนข้อความสั่งการ/เกษียนหรือวางภาพลายมือชื่อลงเนื้อหาไม่ได้ (จะทำให้ลายมือชื่อเดิมเสีย) ลงนามดิจิทัลเพิ่มได้อย่างเดียว
- หนังสือจากแม่แบบ: **ต้องออกเลขก่อนลงนามดิจิทัล** เพราะประทับเลขหลังลงนามดิจิทัลไม่ได้ ระบบกันไว้และไม่ใช้เลขไปเปล่าๆ
- ดาวน์โหลดใบรับรอง CA ทดสอบได้จากตัวดู PDF หรือเมนูลายมือชื่อของฉัน เพื่อตั้งให้ Adobe Reader บนเครื่องทดสอบเชื่อถือ
  (ห้ามติดตั้งเป็นใบรับรองที่เชื่อถือบนเครื่องที่ใช้งานจริง)
- ปิดการลงนามดิจิทัลได้ด้วย `ESARABAN_DIGITAL_SIGNING=False` ใน .env.docker
- ใช้งานจริงต้องใช้ใบรับรองจากผู้ให้บริการออกใบรับรองที่ได้รับอนุญาต และเพิ่มการประทับเวลา (timestamp) ตรวจสอบข้อกำหนดกับผู้รับผิดชอบก่อน

## Audit Log และการแจ้งเตือน (ขั้นตอนที่ 8A)

- **Audit Log** (เมนูสำหรับผู้ดูแลระบบและผู้ตรวจสอบ): บันทึกการเข้าสู่ระบบ/ออกจากระบบ/เข้าสู่ระบบไม่สำเร็จ การจัดการผู้ใช้และบทบาท
  การมอบหมายปฏิบัติราชการแทน การตั้งค่า (เส้นทางการเสนอ หัวหนังสือ) การออกเลขและยกเลิกเลข และทุกเหตุการณ์ของเอกสาร
  (ลงทะเบียน เปิดดู ดาวน์โหลด เสนอ สั่งการ ลงนาม สั่งการ/เกษียน ออกเลข) พร้อมผู้ทำ เวลา และ IP
- เพิ่มได้อย่างเดียว: แก้ไข/ลบผ่านโปรแกรมไม่ได้ และมี trigger ในฐานข้อมูล PostgreSQL ห้าม UPDATE/DELETE
  แต่ละรายการต่อกันด้วย hash chain (SHA-256) กด **ตรวจความครบถ้วน** เพื่อตรวจว่ามีรายการถูกแก้ ลบ หรือแทรกหรือไม่
- เอกสารชั้นความลับ: Audit Log ไม่แสดงชื่อเรื่อง (ผู้ตรวจสอบไม่มีสิทธิ์อ่านเนื้อหาเอกสาร)
- **การแจ้งเตือน** (กระดิ่งที่มุมล่างของเมนู พร้อมจำนวนที่ยังไม่อ่าน): มีเรื่องรอพิจารณา รอสั่งการ/ลงนาม ถูกส่งกลับแก้ไข (พร้อมเหตุผล)
  ได้รับมอบหมาย (พร้อมข้อสั่งการ) เรื่องที่เสนอเสร็จสิ้น ออกเลขแล้ว และมีผู้ลงนามหรือสั่งการ/เกษียนเอกสารที่ท่านสร้าง
  แจ้งเฉพาะผู้ที่มีสิทธิ์เห็นเอกสาร ยังไม่ส่งอีเมล (ต้องตั้งค่า mail server ของหน่วยงานก่อน)

## ภาพรวม ค้นหาและติดตาม คลังเอกสาร (ขั้นตอนที่ 8B)

- **ภาพรวม** (ผู้บริหาร หัวหน้ากลุ่มงาน ผู้ตรวจสอบ ผู้ดูแลระบบ): หนังสือรับ/ออกเลขเดือนนี้ เรื่องระหว่างเสนอ/ดำเนินการ เรื่องเกินกำหนด
  เวลาเฉลี่ยจนเสร็จ กราฟรายเดือน 6 เดือน สถานะ และเรื่องค้างแยกกลุ่มงาน พร้อมรายการงานที่เกินกำหนดว่าค้างอยู่ที่ใคร
  หัวหน้ากลุ่มงานเห็นเฉพาะกลุ่มงานของตน ผู้ดูแลระบบและผู้ตรวจสอบเห็นเฉพาะตัวเลขรวม ไม่เห็นชื่อเรื่อง
- **ค้นหาและติดตาม**: ค้นด้วยเลขทะเบียน เรื่อง หน่วยงาน ผู้รับ หรือข้อความในหนังสือ กรองประเภท สถานะ กลุ่มงาน ช่วงวันที่
  เรื่องด่วน เรื่องเกินกำหนด หรือเรื่องที่รอท่าน ผลลัพธ์บอกว่าตอนนี้อยู่ที่ใครและกำหนดเมื่อไร
- **คลังเอกสาร**: เจ้าหน้าที่สารบรรณจัดเก็บเรื่องที่เสร็จแล้ว ระบุหมวด/แฟ้มและอายุการเก็บ (1/5/10/20 ปี หรือตลอดไป)
  เรื่องที่จัดเก็บอ่านได้อย่างเดียว นำออกได้เมื่อต้องดำเนินการต่อ (ระบุเหตุผล) หน้าคลังแสดงเรื่องที่ครบอายุการเก็บ
  ระบบไม่ทำลายเอกสารเอง การทำลายต้องผ่านคณะกรรมการตามระเบียบงานสารบรรณ

## รายงานและไฟล์ Word (ขั้นตอนที่ 8C)

- เมนู **รายงาน** (ผู้บริหาร หัวหน้ากลุ่มงาน เจ้าหน้าที่สารบรรณ): ทะเบียนหนังสือรับ ทะเบียนหนังสือส่ง และเรื่องค้าง/เกินกำหนด
  เลือกช่วงวันที่และกลุ่มงาน แล้วดาวน์โหลดเป็น **Excel** หรือ **PDF** (A4 แนวนอน ค้นหาข้อความได้ PDF สูงสุด 1,500 รายการ)
  รายงานมีเฉพาะเอกสารที่ผู้ดาวน์โหลดมีสิทธิ์เห็น และการดาวน์โหลดทุกครั้งบันทึกใน Audit Log
- หน้า **Audit Log** ดาวน์โหลดเป็น Excel ได้ตามเงื่อนไขที่ค้นหาอยู่ (สูงสุด 50,000 รายการล่าสุด)
- หนังสือจากแม่แบบ: ปุ่ม **ดาวน์โหลดไฟล์ Word (.docx)** ที่หน้ารายละเอียด จัดหน้าตามแม่แบบเดียวกับ PDF ใช้ฟอนต์ TH SarabunPSK 16
  ถ้าออกเลขแล้วมีเลขที่และวันที่ให้ ไฟล์ Word สร้างจากข้อความ จึงไม่มีลายมือชื่อและข้อความสั่งการ/เกษียน ฉบับทางการคือ PDF ในระบบ
  (เครื่องที่เปิดไฟล์ต้องมีฟอนต์ TH SarabunPSK ซึ่งเป็นฟอนต์มาตรฐานของหน่วยงานราชการ)

## ทดสอบทั้งระบบและความปลอดภัย (ขั้นตอนที่ 9)

ไฟล์ `apps/core/tests_e2e.py` ทดสอบผ่านหน้าเว็บจริงตั้งแต่ต้นจนจบ
- หนังสือรับ: ลงทะเบียน → เสนอ → หัวหน้าเสนอต่อ → ผู้บริหารสั่งการและมอบหมาย → เจ้าหน้าที่ดำเนินการเสร็จ → จัดเก็บเข้าคลัง
- หนังสือส่ง: ร่างจากแม่แบบ → เสนอ → อนุมัติ → ออกเลข → ลงนามดิจิทัล (ตรวจลายมือชื่อผ่าน) → ไฟล์ Word → ทะเบียนส่ง → จัดเก็บ
- ทุก URL ของระบบต้องเข้าสู่ระบบ ผ่านรหัสผ่านอย่างเดียวไม่พอต้องผ่าน MFA, CSRF, header ความปลอดภัย,
  สิทธิ์ของแต่ละบทบาท, ไฟล์ปลอมนามสกุล .pdf, และค่าสำหรับ server จริงผ่าน `manage.py check --deploy`

มาตรการความปลอดภัยที่มีในระบบ
- เข้าสู่ระบบด้วยรหัสผ่าน (อย่างน้อย 12 ตัว) + MFA ทุกคน ล็อกชั่วคราวเมื่อผิดหลายครั้ง ไม่ใช้งาน 30 นาทีออกจากระบบอัตโนมัติ
- HTTPS + HSTS, cookie แบบ Secure/HttpOnly/SameSite, CSRF, X-Frame-Options, Content-Security-Policy, Permissions-Policy
- สิทธิ์ตามบทบาทและกลุ่มงาน ชั้นความลับ แยกหน้าที่ (ผู้ดูแลระบบ/ผู้ตรวจสอบไม่อ่านเอกสาร) เอกสารที่ไม่มีสิทธิ์ตอบ 404
- ไฟล์ตรวจว่าเป็น PDF จริงและไม่มี JavaScript เข้ารหัสก่อนเก็บ ส่งไฟล์ผ่านการตรวจสิทธิ์และบันทึกประวัติทุกครั้ง
- Audit Log แบบ append-only + hash chain, Secret ทั้งหมดอยู่ใน environment variables
- รายงาน Excel กันสูตรอันตราย (formula injection)
- ถ้าหน้าใดใช้งานไม่ได้เพราะ Content-Security-Policy ตั้ง `ESARABAN_CSP_REPORT_ONLY=True` ใน .env.docker ชั่วคราว แล้วแจ้งผู้พัฒนา

## การแก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| `password authentication failed for user "esaraban_app"` | รหัสผ่านใน `DATABASE_URL` ไม่ตรงกับข้อ 3 |
| `encoding "UTF8" does not match locale` | ใช้ `create_db.sql` ฉบับนี้ ซึ่งกำหนด locale `C` แล้ว |
| `permission denied to create database` ตอนรัน test | ผู้ใช้ฐานข้อมูลยังไม่มีสิทธิ์ CREATEDB ให้รัน `ALTER ROLE esaraban_app CREATEDB;` ด้วยผู้ใช้ postgres |
| `ImproperlyConfigured: Set the SECRET_KEY environment variable` | ยังไม่ได้สร้างไฟล์ `.env` (ข้อ 4) |
| หน้าเว็บไม่มีสี ฟอนต์ไม่ใช่ Sarabun | ยังไม่ได้รันข้อ 5 หรือดาวน์โหลดไม่ครบ |
| รหัส MFA ผิดตลอดทั้งที่พิมพ์ถูก | เวลาบนมือถือหรือเครื่อง server ไม่ตรง ให้ตั้งเวลาอัตโนมัติทั้งสองเครื่อง |

## ความปลอดภัยที่มีแล้วในขั้นนี้

- ความลับทั้งหมดอยู่ใน `.env` ซึ่งไม่ถูก commit
- ผู้ใช้ใช้ UUID เป็นรหัส เพื่อไม่ให้เดาลำดับจาก URL ได้
- รหัสผ่านอย่างน้อย 12 ตัวอักษร และห้ามใช้รหัสที่พบบ่อย
- Session หมดอายุเมื่อไม่ใช้งาน 30 นาที และเมื่อปิดเบราว์เซอร์
- ป้องกัน clickjacking (`X-Frame-Options: DENY`) และ MIME sniffing
- `prod.py` บังคับ HTTPS, HSTS, secure cookie และปฏิเสธ SECRET_KEY ที่อ่อน
- ไฟล์เอกสารเก็บใน `private_storage` ซึ่งไม่มี URL สาธารณะ
- ไม่โหลด CSS/JS จาก CDN ขณะใช้งาน
