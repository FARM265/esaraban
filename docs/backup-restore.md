# การสำรองและกู้คืนข้อมูล

## 1. ต้องสำรองอะไรบ้าง

| ข้อมูล | อยู่ที่ | สำรองด้วย |
|---|---|---|
| ฐานข้อมูล (ทะเบียน, ผู้ใช้, เส้นทางการเสนอ, Audit Log) | volume `pgdata` | สคริปต์สำรอง → `db.dump` |
| ไฟล์เอกสาร (เข้ารหัสแล้ว) | volume `private_storage` | สคริปต์สำรอง → `private_storage.tar.gz` |
| ไฟล์ตั้งค่า `.env.docker` | โฟลเดอร์โปรเจกต์ | **สำรองเองแยกต่างหาก** ครั้งเดียวหลังติดตั้ง และทุกครั้งที่แก้ |
| ใบรับรอง HTTPS | `docker/certs` | สำรองเองแยกต่างหาก |

> **คำเตือนเรื่อง `SECRET_KEY`**
> ไฟล์เอกสารทุกไฟล์และค่า MFA ถูกเข้ารหัสด้วยกุญแจที่สร้างจาก `SECRET_KEY` ใน `.env.docker`
> - ถ้า `.env.docker` หาย ชุดสำรองทั้งหมด **เปิดไฟล์เอกสารไม่ได้** และผู้ใช้ทุกคนต้องตั้ง MFA ใหม่ ไม่มีวิธีกู้
> - ห้ามเปลี่ยน `SECRET_KEY` หลังเริ่มใช้งาน
> - ห้ามเก็บ `.env.docker` ไว้ในโฟลเดอร์ `backups` ข้างชุดสำรอง เพราะใครได้ทั้งสองอย่างจะเปิดเอกสารได้ทั้งหมด
>   ให้เก็บแยก เช่น พิมพ์เก็บในซองปิดผนึกในตู้นิรภัย หรือในระบบจัดเก็บรหัสผ่านของหน่วยงาน

## 2. สำรองข้อมูล

รันจากโฟลเดอร์โปรเจกต์ ขณะระบบทำงานอยู่ได้ (ไม่ต้องหยุดระบบ)

```bash
sh scripts/backup.sh                    # Linux server
KEEP_DAYS=60 sh scripts/backup.sh       # เก็บชุดสำรองไว้ 60 วัน (ค่าเริ่มต้น 30)
```

```powershell
powershell -ExecutionPolicy Bypass -File scripts\backup.ps1               # Windows
powershell -ExecutionPolicy Bypass -File scripts\backup.ps1 -KeepDays 60
```

ผลลัพธ์อยู่ใน `backups/<วันเวลา>/` มี 3 ไฟล์: `db.dump`, `private_storage.tar.gz`, `SHA256SUMS`
สคริปต์ตรวจว่าเปิดชุดสำรองได้จริงก่อนจบ ถ้าขั้นใดผิดพลาดจะหยุดและแจ้ง

### ตั้งเวลาสำรองอัตโนมัติ

**Linux (cron)** ทุกวัน 01:30 น. — `crontab -e` แล้วเพิ่ม

```
30 1 * * * cd /opt/esaraban && sh scripts/backup.sh >> backups/backup.log 2>&1
```

**Windows (Task Scheduler)** สร้างงานใหม่ เลือก "Run whether user is logged on or not"
- Program: `powershell.exe`
- Arguments: `-ExecutionPolicy Bypass -File scripts\backup.ps1`
- Start in: `C:\Projects\esaraban`

### กฎ 3-2-1

ชุดสำรองบน server เครื่องเดียวกันไม่พอ ถ้าดิสก์เสียหรือโดนมัลแวร์จะหายพร้อมกัน ให้มี
**3 ชุด** บน **2 สื่อ** และ **1 ชุดอยู่นอกสถานที่** (หรือแยกออฟไลน์) เช่น คัดลอก `backups/` ไปยัง NAS
ของหน่วยงานทุกวัน และลงดิสก์ภายนอกที่เก็บแยกทุกสัปดาห์ ชุดสำรองมีข้อมูลเอกสาร (แม้ไฟล์จะเข้ารหัส)
จึงต้องเก็บในที่ที่ควบคุมการเข้าถึงเหมือน server

## 3. กู้คืนข้อมูล

> การกู้คืน **ลบข้อมูลปัจจุบันทั้งหมด** แล้วแทนด้วยชุดสำรอง ข้อมูลที่บันทึกหลังเวลาสำรองจะหาย

1. ตรวจว่า `.env.docker` เป็นไฟล์เดียวกับตอนสำรอง (SECRET_KEY ต้องตรงกัน) ถ้าเป็นเครื่องใหม่ให้นำไฟล์ที่สำรองไว้มาวางก่อน
2. รัน (ระบุโฟลเดอร์ชุดสำรอง)
   ```bash
   sh scripts/restore.sh backups/20261120-013000
   ```
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\restore.ps1 backups\20261120-013000
   ```
3. สคริปต์ตรวจ checksum แล้วให้พิมพ์ `RESTORE` เพื่อยืนยัน จากนั้นหยุด web/nginx กู้ฐานข้อมูล
   (ทำทั้งหมดในธุรกรรมเดียว ถ้าพลาดฐานข้อมูลเดิมไม่เปลี่ยน) แทนที่ไฟล์เอกสาร และเปิดระบบกลับ
4. หลังกู้คืน
   - เข้าสู่ระบบและเปิดเอกสารสัก 2–3 ฉบับ ว่าแสดงผลได้ (ยืนยันว่า SECRET_KEY ถูก)
   - ผู้ตรวจสอบกด **ตรวจความครบถ้วน** ใน Audit Log ผลต้องผ่าน
   - ดู **สถานะระบบ**
   - บันทึกเหตุการณ์กู้คืน (วันเวลา ชุดสำรองที่ใช้ ผู้ดำเนินการ เหตุผล) ตามระเบียบของหน่วยงาน

### กู้คืนบนเครื่องใหม่

ติดตั้งตาม [คู่มือติดตั้ง](install.md) ข้อ 3.1–3.4 โดยใช้ `.env.docker` และ `docker/certs` ที่สำรองไว้
(ไม่ต้อง createsuperuser) คัดลอกโฟลเดอร์ชุดสำรองมาไว้ใน `backups/` แล้วทำข้อ 3 ข้างต้น

## 4. ซ้อมกู้คืน

ชุดสำรองที่ไม่เคยทดลองกู้ ถือว่ายังไม่มีชุดสำรอง ให้ซ้อมอย่างน้อยทุก 6 เดือน **บนเครื่องทดสอบ ไม่ใช่เครื่องจริง**
ทำตาม "กู้คืนบนเครื่องใหม่" แล้วบันทึกว่าใช้เวลากี่นาที ข้อมูลล่าสุดเป็นของวันที่เท่าไร และพบปัญหาอะไร
เมื่อเสร็จให้ลบข้อมูลบนเครื่องทดสอบ
