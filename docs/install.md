# คู่มือติดตั้งระบบ E-Saraban บน server ภายใน

> ระบบนี้เป็น **ระบบทดลอง** ห้ามใช้ข้อมูลจริงหรือข้อมูลลับของสำนักงานจนกว่าผู้รับผิดชอบจะตรวจสอบและอนุมัติ
> และห้ามเชื่อมต่อกับข้อมูลราชการจริงโดยไม่ได้รับอนุญาต ก่อนเปิดใช้งานจริงให้ทำตาม [รายการตรวจก่อนใช้งานจริง](security-checklist.md)

## 1. ภาพรวม

```
ผู้ใช้ (เบราว์เซอร์ในเครือข่ายภายใน)
        │ HTTPS พอร์ต 443
        ▼
  nginx ── ใบรับรอง HTTPS, ส่งไฟล์ CSS/JS
        │
        ▼
  web (Django + Gunicorn) ── ตรวจสิทธิ์ทุกคำขอ, ถอดรหัสไฟล์เอกสารเมื่อมีสิทธิ์
        │                     volume: private_storage (ไฟล์เอกสารที่เข้ารหัสแล้ว)
        ▼
  db (PostgreSQL 16) ── ไม่เปิดพอร์ตออกนอกเครื่อง   volume: pgdata
```

ข้อมูลที่ต้องดูแลมี 4 อย่าง: ฐานข้อมูล (`pgdata`), ไฟล์เอกสาร (`private_storage`), ไฟล์ตั้งค่า `.env.docker`
และใบรับรอง HTTPS ใน `docker/certs` วิธีสำรองดูที่ [การสำรองและกู้คืนข้อมูล](backup-restore.md)

## 2. ความต้องการของเครื่อง

| รายการ | ขั้นต่ำสำหรับสำนักงานขนาดเล็ก (ไม่เกิน 100 ผู้ใช้) |
|---|---|
| ระบบปฏิบัติการ | Linux server รุ่นที่ยังได้รับการปรับปรุงความปลอดภัย (เช่น Ubuntu Server LTS) |
| ซอฟต์แวร์ | Docker Engine พร้อม Docker Compose plugin |
| CPU / RAM | 2 core / 4 GB (แนะนำ 4 core / 8 GB) |
| พื้นที่ดิสก์ | 50 GB ขึ้นไป แยกพื้นที่สำหรับชุดสำรองข้อมูล |
| เครือข่าย | ชื่อเครื่องในเครือข่ายภายใน (DNS) เช่น `esaraban.local` และเปิดเฉพาะพอร์ต 443 (และ 80 เพื่อเปลี่ยนไป HTTPS) ภายในเครือข่าย |

ตัวเลขข้างต้นเป็นค่าประมาณสำหรับเริ่มต้น ให้ฝ่าย IT ปรับตามปริมาณเอกสารจริง

## 3. ติดตั้ง

ทำบน server ด้วยผู้ใช้ที่ใช้คำสั่ง `docker` ได้ (ตัวอย่างเป็นคำสั่ง Linux)

### 3.1 นำโค้ดไปไว้บน server

คัดลอกโฟลเดอร์โปรเจกต์ไปไว้บน server เช่น `/opt/esaraban` แล้ว `cd /opt/esaraban`

### 3.2 สร้างไฟล์ตั้งค่า `.env.docker`

```bash
cp .env.docker.example .env.docker
chmod 600 .env.docker
# สร้างค่าลับ 3 ค่า (รันทีละบรรทัด แล้วคัดลอกผลไปใส่ในไฟล์)
docker run --rm python:3.12-slim python -c "import secrets; print(secrets.token_urlsafe(50))"   # SECRET_KEY
docker run --rm python:3.12-slim python -c "import secrets; print(secrets.token_hex(24))"       # POSTGRES_PASSWORD
docker run --rm python:3.12-slim python -c "import secrets; print(secrets.token_hex(24))"       # POSTGRES_APP_PASSWORD
```

แก้ค่าใน `.env.docker`:

| ตัวแปร | ค่า |
|---|---|
| `SERVER_NAME` | ชื่อเครื่องที่ผู้ใช้พิมพ์ในเบราว์เซอร์ เช่น `esaraban.local` |
| `SECRET_KEY` | ค่าสุ่มยาวจากคำสั่งแรก **ห้ามเปลี่ยนหลังเริ่มใช้งาน** (ใช้ถอดรหัสไฟล์เอกสารและ MFA) |
| `ALLOWED_HOSTS` | `esaraban.local,127.0.0.1` (ต้องมี 127.0.0.1 สำหรับ health check) |
| `CSRF_TRUSTED_ORIGINS` | `https://esaraban.local` |
| `POSTGRES_PASSWORD` | ค่าสุ่มจากคำสั่งที่สอง (ผู้ใช้เจ้าของฐานข้อมูล ใช้ตอน migrate) |
| `POSTGRES_APP_USER` | เพิ่มบรรทัดใหม่ เช่น `esaraban_rt` (ผู้ใช้แบบจำกัดสิทธิ์ที่ระบบใช้ขณะทำงาน) |
| `POSTGRES_APP_PASSWORD` | เพิ่มบรรทัดใหม่ ค่าสุ่มจากคำสั่งที่สาม |
| `ORG_CODE` | รหัสหนังสือของหน่วยงาน เช่น `ปช XXXX` |
| `ESARABAN_SIGN_REQUIRE_OTP` | (ไม่บังคับ) `True` = ต้องกรอกรหัส 6 หลักจากแอปทุกครั้งที่ลงนาม ค่าเริ่มต้น `False` ดู [รายการตรวจก่อนใช้งานจริง](security-checklist.md) |
| `SECURE_HSTS_SECONDS` | `0` ระหว่างใช้ใบรับรองทดลอง เปลี่ยนเป็น `31536000` หลังติดตั้งใบรับรองจริง (ข้อ 3.3) |

**สำรองไฟล์ `.env.docker` ทันที** ไว้ในที่ปลอดภัยแยกจาก server (เช่น ตู้นิรภัยหรือระบบจัดเก็บรหัสผ่านของหน่วยงาน)
ถ้าไฟล์นี้หาย จะเปิดไฟล์เอกสารที่สำรองไว้ไม่ได้อีกเลย

### 3.3 ใบรับรอง HTTPS ของหน่วยงาน

ถ้าไม่มีไฟล์ในโฟลเดอร์ `docker/certs` ระบบจะสร้างใบรับรองทดลอง (self-signed) ให้ ซึ่งเบราว์เซอร์จะเตือนทุกครั้ง
สำหรับใช้งานจริงให้ขอใบรับรองจากฝ่าย IT แล้ววาง

- `docker/certs/server.crt` ใบรับรองรวม intermediate certificate
- `docker/certs/server.key` กุญแจลับ (ตั้งสิทธิ์ `chmod 600`)

แล้วแก้ `SECURE_HSTS_SECONDS=31536000` ใน `.env.docker`
(HSTS ทำให้เบราว์เซอร์เข้าแบบ HTTPS เท่านั้นเป็นเวลา 1 ปี เปิดเมื่อใบรับรองจริงพร้อมแล้วเท่านั้น)

### 3.4 เริ่มระบบ

```bash
docker compose --env-file .env.docker up -d --build
docker compose --env-file .env.docker ps          # รอจน db/web ขึ้น healthy และ nginx ขึ้น running
docker compose --env-file .env.docker exec web python manage.py createsuperuser
```

ตอนเริ่มทุกครั้ง ระบบจะ migrate ฐานข้อมูล สร้าง/ปรับสิทธิ์ผู้ใช้ฐานข้อมูลแบบจำกัดสิทธิ์ และตรวจค่าความปลอดภัยให้เอง

### 3.5 ตรวจหลังติดตั้ง

1. เปิด `https://esaraban.local` เข้าสู่ระบบด้วยผู้ดูแลระบบจากข้อ 3.4 แล้วตั้งค่า MFA ด้วยแอป Authenticator บนมือถือ
   และเก็บรหัสสำรอง 10 รหัสไว้ในที่ปลอดภัย
2. เมนู **สถานะระบบ** ทุกข้อต้องเป็นเครื่องหมายถูก รวมถึง "ผู้ใช้ฐานข้อมูลขณะทำงาน" ต้องเป็นผู้ใช้ที่จำกัดสิทธิ์
3. รันเทสต์ (ใช้เวลาประมาณ 2 นาที ผลต้องเป็น `OK`):
   ```bash
   docker compose --env-file .env.docker exec -e DJANGO_SETTINGS_MODULE=config.settings.dev web python manage.py test apps --noinput
   ```
4. ทดลองสำรองข้อมูลด้วย `sh scripts/backup.sh` และตั้งเวลาสำรองอัตโนมัติ ตาม [การสำรองและกู้คืนข้อมูล](backup-restore.md)

## 4. ตั้งค่าเริ่มต้นสำหรับสำนักงาน (ผู้ดูแลระบบ)

ทำตามลำดับนี้ในหน้าเว็บ

1. **กลุ่มงาน** เพิ่มกลุ่มงานตามโครงสร้างสำนักงาน (กลุ่มงานย่อยเลือก "สังกัด" ได้)
2. **ผู้ใช้และสิทธิ์** สร้างบัญชีผู้ใช้ทุกคน กำหนดกลุ่มงานที่สังกัด ระดับชั้นความลับที่เข้าถึงได้ และบทบาท
   (เจ้าหน้าที่สารบรรณ, เจ้าหน้าที่ทั่วไป, หัวหน้ากลุ่มงาน, ผู้บริหาร, ผู้ดูแลระบบ, ผู้ตรวจสอบ)
   ผู้ใช้ใหม่ต้องเปลี่ยนรหัสผ่านและตั้ง MFA เมื่อเข้าสู่ระบบครั้งแรก
3. **ทะเบียนเลขหนังสือ** ตรวจชุดทะเบียน (รับ ส่ง บันทึกข้อความ คำสั่ง ประกาศ) แก้รหัสหน่วยงานและรูปแบบเลขให้ตรงกับที่ใช้จริง
4. **หัวหนังสือ** ใส่ชื่อส่วนราชการ ที่ตั้ง ส่วนราชการเจ้าของเรื่องค่าเริ่มต้น และอัปโหลดภาพตราครุฑของหน่วยงาน
5. **เส้นทางการเสนอ** ตรวจเส้นทางมาตรฐาน แก้ขั้นตอนให้ตรงกับสายการบังคับบัญชาของสำนักงาน
6. ให้ผู้บริหารและหัวหน้ากลุ่มงานอัปโหลด **ลายมือชื่อของฉัน**

## 5. งานดูแลระบบประจำ

| ความถี่ | งาน |
|---|---|
| ทุกวัน (อัตโนมัติ) | สำรองข้อมูล และคัดลอกออกนอกเครื่อง |
| ทุกสัปดาห์ | ดู **สถานะระบบ** และพื้นที่ดิสก์ (`df -h`, `docker system df`) |
| ทุกเดือน | ผู้ตรวจสอบกด **ตรวจความครบถ้วน** ใน Audit Log, ทบทวนผู้ใช้ที่ย้าย/ลาออก (ระงับบัญชี), ทบทวนการมอบหมายปฏิบัติราชการแทน |
| ทุก 6 เดือน | ซ้อมกู้คืนข้อมูลบนเครื่องทดสอบ ตาม [การสำรองและกู้คืนข้อมูล](backup-restore.md) |
| เมื่อมีรุ่นใหม่ | ปรับปรุงระบบตามข้อ 6 |

## 6. ปรับปรุงเป็นรุ่นใหม่

```bash
sh scripts/backup.sh                                      # สำรองก่อนเสมอ
# คัดลอกโค้ดรุ่นใหม่ทับโฟลเดอร์โปรเจกต์ (ไม่ทับ .env.docker และ docker/certs)
docker compose --env-file .env.docker up -d --build
docker compose --env-file .env.docker exec -e DJANGO_SETTINGS_MODULE=config.settings.dev web python manage.py test apps --noinput
```

นอกจากนี้ให้ปรับปรุง image พื้นฐานเป็นระยะเพื่อรับแพตช์ความปลอดภัย:
`docker compose --env-file .env.docker build --pull` แล้ว `up -d`

**ห้ามใช้ `docker compose down -v`** เพราะจะลบฐานข้อมูลและไฟล์เอกสารทั้งหมด

## 7. แก้ปัญหาเบื้องต้น

| อาการ | วิธีตรวจ |
|---|---|
| `web` ไม่ขึ้น healthy | `docker compose --env-file .env.docker logs web --tail 100` |
| `port is already allocated` | มีโปรแกรมอื่นใช้พอร์ต 80/443 อยู่ ให้ปิดก่อน |
| หน้าเว็บไม่มีสี/ไม่มีฟอนต์ | กด Ctrl+F5 ถ้ายังไม่หาย ดู log ของ nginx |
| หน้าใดใช้งานไม่ได้เพราะ Content-Security-Policy | ตั้ง `ESARABAN_CSP_REPORT_ONLY=True` ชั่วคราว แล้ว `up -d` และแจ้งผู้พัฒนา |
| ผู้ใช้ทำมือถือหาย เข้า MFA ไม่ได้ | ผู้ดูแลระบบกด "รีเซ็ต MFA" ที่หน้าผู้ใช้ (บันทึกใน Audit Log) |
