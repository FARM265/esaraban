# รายการตรวจก่อนใช้งานจริง

ระบบนี้พัฒนาเป็น **ระบบทดลอง** ก่อนนำข้อมูลจริงเข้าระบบ ต้องให้ผู้รับผิดชอบตรวจและอนุมัติทุกข้อ

## 1. ข้อกำหนดและการอนุมัติ

- [ ] ผู้รับผิดชอบตรวจสอบว่าระบบเป็นไปตามระเบียบสำนักนายกรัฐมนตรีว่าด้วยงานสารบรรณ (และฉบับแก้ไข)
      ระเบียบว่าด้วยการรักษาความลับของทางราชการ กฎหมายว่าด้วยธุรกรรมทางอิเล็กทรอนิกส์ กฎหมายคุ้มครองข้อมูลส่วนบุคคล
      และมาตรฐาน/แนวปฏิบัติที่หน่วยงานต้นสังกัดกำหนด
- [ ] ได้รับอนุญาตเป็นลายลักษณ์อักษรก่อนเชื่อมต่อกับระบบหรือข้อมูลราชการอื่น
- [ ] กำหนดว่าเอกสารชั้นความลับระดับใดนำเข้าระบบได้ (แนะนำให้เริ่มจากเอกสารทั่วไปก่อน)
- [ ] ฝ่าย IT ทดสอบเจาะระบบ (penetration test) หรือประเมินความปลอดภัยแล้ว

## 2. ลายมือชื่ออิเล็กทรอนิกส์

- [ ] รับทราบว่า **ใบรับรองที่ระบบออกให้เป็นใบรับรองทดลอง ไม่มีผลทางกฎหมาย**
      (ในเอกสารและหน้าตรวจลายมือชื่อแสดงคำว่า "ไม่มีผลทางกฎหมาย")
- [ ] ถ้าต้องการลายมือชื่อดิจิทัลที่มีผลทางกฎหมาย ต้องใช้ใบรับรองจากผู้ให้บริการออกใบรับรองที่ได้รับอนุญาต
      และปรับระบบให้ใช้ใบรับรองนั้น ซึ่งยังไม่ได้ทำในรุ่นนี้
- [ ] รับทราบว่า **ภาพลายมือชื่อเพียงอย่างเดียวไม่ใช่ลายมือชื่อดิจิทัล**
- [ ] พิจารณาเปิด `ESARABAN_SIGN_REQUIRE_OTP=True` ใน `.env.docker` เพื่อให้ผู้ลงนามกรอกรหัส 6 หลักจากแอปทุกครั้งที่ลงนาม
      (ช่วงทดลองปิดไว้ตามที่ผู้ใช้ขอ ผู้ลงนามจึงยืนยันด้วยการกดปุ่มซ้ำเท่านั้น ถ้ามีผู้อื่นใช้เครื่องที่ยังเข้าสู่ระบบค้างไว้ จะลงนามแทนได้)

## 2.1 ลงปฏิทิน (Google Calendar)

- [ ] รับทราบว่าปุ่ม "เพิ่มลง Google Calendar" ส่ง ชื่องาน วันที่ สถานที่ และเรื่อง ไปยัง Google ผ่านเบราว์เซอร์ของผู้ใช้
      (ระบบไม่ได้เชื่อมกับบัญชี Google โดยตรง และกันหนังสือชั้นความลับไว้แล้ว) ตรวจว่าเป็นไปตามนโยบายการใช้บริการคลาวด์ของหน่วยงาน

## 3. การตั้งค่า server

- [ ] `.env.docker` ใช้ค่าสุ่มใหม่ทุกค่า ไม่ใช่ค่าตัวอย่าง และตั้งสิทธิ์ `chmod 600`
- [ ] สำรอง `.env.docker` แยกเก็บแล้ว ([การสำรองและกู้คืนข้อมูล](backup-restore.md))
- [ ] ตั้ง `POSTGRES_APP_USER` / `POSTGRES_APP_PASSWORD` แล้ว และหน้า **สถานะระบบ** แสดงว่าระบบใช้ผู้ใช้ฐานข้อมูลแบบจำกัดสิทธิ์
      (ผู้ใช้นี้แก้ไข/ลบ Audit Log ไม่ได้ สร้างตารางไม่ได้ และแก้ประวัติ migration ไม่ได้)
- [ ] ติดตั้งใบรับรอง HTTPS ของหน่วยงานใน `docker/certs` แล้วตั้ง `SECURE_HSTS_SECONDS=31536000`
- [ ] `ESARABAN_CSP_REPORT_ONLY=False` (ค่าเริ่มต้น)
- [ ] firewall เปิดเฉพาะพอร์ต 80/443 ให้เครือข่ายภายใน ไม่เปิดสู่อินเทอร์เน็ต และไม่เปิดพอร์ตฐานข้อมูล
- [ ] ระบบปฏิบัติการ server ตั้งให้ปรับปรุงความปลอดภัยอัตโนมัติ และนาฬิกา sync กับ NTP (เวลาใน Audit Log และลายมือชื่อ)
- [ ] เทสต์ทั้งหมดผ่าน (`manage.py test apps --noinput`)

## 4. บัญชีผู้ใช้

- [ ] ผู้ดูแลระบบทุกคนตั้ง MFA แล้ว และไม่ใช้บัญชีผู้ดูแลระบบร่วมกัน
- [ ] ผู้ดูแลระบบและผู้ตรวจสอบเป็นคนละคน (ระบบออกแบบให้ทั้งสองบทบาทไม่เห็นเนื้อหาเอกสาร)
- [ ] ลบหรือระงับบัญชีทดสอบทั้งหมด และ **ลบข้อมูลทดลองทั้งหมด** ก่อนนำข้อมูลจริงเข้า (แนะนำให้ติดตั้งใหม่บนเครื่องจริง)
- [ ] มีขั้นตอนแจ้งผู้ดูแลระบบเมื่อมีผู้ย้าย/ลาออก เพื่อระงับบัญชีภายในวันเดียวกัน

## 5. การสำรองและเฝ้าระวัง

- [ ] ตั้งเวลาสำรองอัตโนมัติทุกวัน และคัดลอกออกนอกเครื่องตามกฎ 3-2-1
- [ ] ซ้อมกู้คืนบนเครื่องทดสอบสำเร็จอย่างน้อย 1 ครั้งก่อนเปิดใช้
- [ ] กำหนดผู้รับผิดชอบดู **สถานะระบบ** ทุกสัปดาห์ และกด **ตรวจความครบถ้วน** ใน Audit Log ทุกเดือน
      ถ้าผลไม่ผ่าน (มีการแก้ไขบันทึกนอกระบบ) ให้แจ้งผู้บังคับบัญชาและเก็บหลักฐานทันที
- [ ] กำหนดระยะเวลาเก็บ Audit Log และชุดสำรองตามระเบียบของหน่วยงาน

## 6. สิ่งที่ระบบรุ่นนี้ยังไม่มี

แจ้งผู้รับผิดชอบเพื่อพิจารณาว่าจำเป็นก่อนใช้งานจริงหรือไม่

- การเชื่อมต่อระบบสารบรรณของหน่วยงานอื่น (รับ-ส่งหนังสือข้ามหน่วยงาน)
- ลายมือชื่อดิจิทัลด้วยใบรับรองที่มีผลทางกฎหมาย
- การแจ้งเตือนทางอีเมลหรือช่องทางอื่นนอกระบบ (ปัจจุบันแจ้งเตือนในระบบเท่านั้น)
- การทำลายเอกสารตามระเบียบ (ปัจจุบันมีการจัดเก็บเข้าคลังและยกเลิก แต่ไม่ลบเอกสาร)
